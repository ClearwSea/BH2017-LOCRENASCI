# Windows桌面构建器

构建器把指定1.9、2.4客户端、7.x资源、项目服务端及兼容规则和外部补充资源组装为单APK与外置视频包。

完整构建建议额外预留20 GiB可用空间，输入与工具包另计；多轮构建建议30 GiB以上。详见[空间预留](build.md#本地空间)。

## 目录与启动

程序包解压后保留`构建器.exe`和`app/`，配套工具位于同级`tools/`。外部补充资源ZIP单独存放并在界面中选择。双击EXE启动，构建器不下载依赖、不安装系统组件，也不修改系统环境变量。

GUI源码入口为`python -B launch_gui.py <套件目录>`；`src/tools/DesktopLauncher.cs`可用Windows .NET Framework C#编译器编译成窗口程序入口。

## 输入

- 指定1.9原始APK与2.4参考APK，支持版本见`src/profiles/android-launcher-20261102.json`。
- 7.x的`StreamingAssets`目录，直接包含`Audio/`与`Video/`。相近版本需要满足所用语音和视频覆盖。
- 独立补充资源ZIP，含7张配套图片及缺失旧CG，格式见[补充资源说明](../assets/README.md)。
- 本地离线工具目录，默认套件中的`tools/`。
- 与输入、工具和程序分开的输出目录。

选择输入后，点击“检查路径”，再点击“开始构建”。进度和日志在窗口下方显示；点击“停止构建”可结束当前任务，已生成的中间文件和日志保留在输出目录中。

点击左侧1.9、2.4、7.x或补充资源名称，可查看参考信息。APK/ZIP支持手动计算SHA-256；7.x按音视频文件名和大小快速核对。核对在后台运行，可随时取消；文件与参考不同也可以继续构建。

## 工具包

配套工具包固定提供构建用Python及依赖、JDK、Android SDK、Gradle及Chaquopy离线缓存、ARM交叉编译器、FFmpeg、vgmstream和Android Python依赖。第三方组件遵守各自许可证，独立于项目源码。

## 签名

点击界面中的“签名设置”可打开填写说明。

四项全部留空也可构建。首次构建会在`user-data/keys/local-build.jks`生成本机签名密钥，此后继续复用；默认别名为`builder`，默认密码为`android`。保留密钥文件和对应填写方式，后续APK即可保持相同签名。

使用已有密钥时，填写以下内容：

| 字段 | 填写内容 | 留空时 |
| --- | --- | --- |
| 密钥路径 | 已有的`.jks`或`.keystore`文件 | 自动生成或复用本机密钥 |
| 别名 | 文件中用于签名的密钥别名 | 使用`builder` |
| 密钥库密码 | 打开密钥库的密码 | 使用`android` |
| 密钥密码 | 该别名对应密钥的密码 | 使用密钥库密码 |

填写内容必须与所选密钥一致；修改输入框不会重建已有密钥或修改其密码。密钥路径和别名会保留，密码每次打开默认显示`android`；使用自有密码时需重新填写。

同一应用使用相同签名可覆盖安装并保留数据。密钥丢失后重新生成，或改用其他密钥，通常需要卸载旧应用再安装；卸载前请导出存档并确认备份已保存在应用目录之外。已导出的兼容存档可以导入新签名版本。

密码只传给本次子进程，不写入路径设置、构建配置或命令行。`user-data/`保存本机路径、日志和密钥，不作为通用程序包或源码发布。

## 安装与资源导入

每次构建在输出目录创建新的日期时间子目录，其中包含：

- `崩坏3·2017 独立版.apk`。
- `client-videos.zip`，与该APK配套。
- `build-result.json`与本机构建配置。
- `work/`中的中间文件、阶段日志及构建记录。

安装生成的APK，在启动界面导入同次构建的`client-videos.zip`与兼容存档，再启动游戏。更新已有安装时沿用原签名，并选择对应构建的资源包。
