## 开始前：沟通方式与网络自测

### 用用户听得懂的话推进

根据用户的提问和反馈判断其熟悉程度，不给用户贴“技术水平低”的标签。用户不熟悉构建、签名、文件路径等概念时，必须在**每一步**用简短、通俗的话说明：现在要做什么、为什么要做、当前有什么阻碍、下一步需要用户做什么，以及该步骤实际需要注意的事项。没有阻碍或不需要用户操作时直接说清楚，不制造问题，也不要堆砌整篇技术文档。

在即将进入依赖用户选择或材料的步骤前，及时预提问，不要等到操作失败才问。首次先问设备和已有材料，下载前说明文件大小与存放位置，安装前确认新装还是覆盖更新及存档备份，生成存档前解释新号与体验号区别。一次只问当前及紧接着下一步必需的少量问题；已明确的答案和授权直接复用，能自行检查的先检查。等待回答时继续不依赖该答案的工作。

例如：“我先检查下载速度，因为构建工具包比较大，避免下载到一半才发现网络不通。你现在不用操作；接下来请告诉我电脑还有多少可用空间，或者允许我直接检查。”网络受阻时则说明具体影响和替代方案，而不是只抛出报错或说“请自行解决”。

### 先测试实际下载环境，不假定有可靠代理

默认用户的 Agent **没有可靠的网络代理**。在下载大文件之前，先用可用工具做一次有超时、有流量上限的快速检查。即使已能阅读仓库，也不能据此认定 Release 大附件能顺畅下载；Agent 云端的网络结果也不代表用户电脑的网络。

1. 在实际负责下载文件的环境中，检查仓库/Release 页面或 GitHub API 的连通性，记录响应状态和耗时。单次连接超时可设约 10 秒、请求总时限约 20 秒；失败时有限重试，不无休止等待。
2. 从实际 Release 元数据中取得一个真实附件 URL，跟随重定向测试文件下载。优先读取约 1–4 MiB 的小段数据，设置约 20 秒总时限和硬性读取量上限，记录实际字节数、平均速度及是否中断。服务器忽略 Range 时也要主动停止，不能把测速变成整包下载。仅做 HEAD 请求不能证明下载速度。
3. 结合实际附件大小估算下载耗时。例如，连续超时、连接反复中断，或大包测速持续低于约 200 KiB/s，应视为质量不佳的信号；这些是判断参考，不是固定通过门槛。只有鉴权失败、API 限流或链接失效时，应区分错误原因，不能全部归因于网络。
4. 不能执行网络请求时，如实说明未能自测；提供用户可以执行的短步骤或命令，并解释需要返回什么结果，不虚构测试成功。

如果连接质量不佳，**必须明确告诉用户“当前环境到 GitHub 的网络连接质量较差”**，附上实际测得的超时、速度或预计等待时间。这可能发生在中国大陆部分网络下，但不能仅凭用户所在地区推断。同步说明构建仍缺哪些下载、其他准备工作能否继续。

随后由你主动制定并尝试可行的 Release 获取方案，不能只让用户“自己找代理”。根据自身工具和用户环境自行选择：可用的官方附件直链、支持续传的下载工具、用户已有且允许使用的代理/其他网络、浏览器下载后交给 Agent，或在获准且网络可用的另一环境下载后传回。需要用户配合时，用人话说明该方案、为什么可行、用户只需完成哪一步。

本文不指定永久有效的加速站或代理地址。第三方中转若确有需要，应先核实可用性并告知用户来源；不向其发送 GitHub 凭据、签名密钥或存档，不关闭 TLS 证书校验。取得文件后对照官方提供的 SHA-256 校验；暂时无法取得官方校验值时明确标记未验证，不宣称文件可信。代理安装、系统设置变更和付费服务按用户授权处理，不以解决下载为由擅自更改环境。

## 1. 先理解用户要得到什么

本项目将用户提供的游戏客户端与资源，结合仓库中的 Python 本地服务端、兼容补丁和 Android 启动组件，组装成可以在兼容 Android 设备上运行的离线版本。正常游玩时服务端随 APK 在手机本地运行，不需要另租服务器或在电脑上常驻 Python 服务。

最终需要交给用户三样东西：

| 文件 | 来源及用途 |
| --- | --- |
| 游戏 APK | 本项目构建生成，安装到手机 |
| `client-videos.zip` | 与 APK 同次生成，在手机启动页选择；不是构建前下载的补充资源包 |
| `account.json` | 兼容旧存档，或由配套存档编辑器生成，在手机启动页选择 |

仓库源码、Windows 构建器 ZIP、外部补充资源 ZIP 都不能直接作为游戏 APK 安装。下载源码本身也不会获得原始游戏资源。

用户只发仓库链接而没有说明目标时，先简要介绍上述用途，再询问是“想构建并游玩”还是“想修改源码”。用户已说明要玩时，继续以下流程，不要让其先学习代码结构。

## 2. 收集最少的必要信息

先查看已提供的文件和环境，再按当前步骤分批补问缺失项；下面是 Agent 需要掌握的信息，不是要求一次性发给新手填写的表格：

- 电脑系统、可用空间，以及允许使用的构建和输出目录。
- 手机型号、Android 版本；已有安装还是首次安装。
- 1.9 APK、2.4 APK、7.x PC Windows 资源是否已准备好，以及实际路径。
- 是否已有兼容存档；新玩家希望从新号开始还是使用满级体验号。
- 覆盖更新时是否保留了原签名密钥和原存档。

默认优先使用发布的 Windows x64 离线构建器。其他电脑系统没有同等现成的已验证流程，不要把 Windows 工具路径直接改成 Linux/macOS 路径后声称可用。纯网页聊天环境只能提供步骤；不能执行本地命令时，应如实说明，并让用户在本地完成对应操作。

公开构建的游戏和 Python 运行时使用 ARM32。不能只凭“骁龙”“64 位”或 Android 版本判断可用性；设备需要原生 ARM32 支持或已具备有效的系统转译能力。可参考 [实测设备](../README.md#已实测设备)及 [Android 兼容说明](android-compatibility.md)。项目不会替用户安装或提供 TANGO；未列出的设备、模拟器及其他架构不能承诺可玩。

完整构建在输入和工具体积之外额外预留 **20 GiB**；保留多轮产物建议 **30 GiB 以上**。手机也需为 APK 安装、内置资源展开和视频导入留出空间，按实际文件体积检查，不沿用电脑的空间要求。

用户也可以用当前环境支持的其他方式提供，例如告知现有文件的绝对路径、上传文件、提供可访问的共享位置或下载链接，无须为了满足目录示例重复搬运大型文件。Agent 要说明自己实际能访问哪种方式；聊天上传受大小限制时，优先引导使用本地路径或其他可访问方式。

可以这样向用户说明：“还需要你提供三份材料：1.9 的 APK、2.4 的 APK，以及 7.x 电脑版游戏资源。上面的三个视频是 README 给出的参考入口，请按视频说明获取文件。下载后放到我刚才指定的文件夹，或者直接告诉我文件在哪；如果拿到的是压缩包，先把路径给我，我来检查内容和是否需要解压。你不需要自己识别里面的代码。”收到后再检查 APK、资源目录和版本结构，帮助定位包含 `Audio/` 与 `Video/` 的 `StreamingAssets`，不要要求新手自行完成技术判断。

原始 APK/补充 ZIP 的参考哈希与大小用于提示；不同不代表一定不能构建。内部原生库指纹、指令前像、表单结构和必要文件的检查则必须通过，不能绕过。7.x 参考比较按文件名和大小进行。补充包结构见 [assets/README.md](../assets/README.md)。

## 4. Windows 构建器：优先的游玩路径

完整解压后的主要布局应为：

```text
BH2017-LOCRENASCI-Builder/
  构建器.exe
  app/                   项目源码及配置
  tools/                 离线工具链
    python/python.exe
    android/
    zig/
    ffmpeg/
    vgmstream/
    wheelhouse/
  user-data/             使用时生成的设置、日志、签名密钥
  output/                默认输出位置，也可另选
```

1. 双击 `构建器.exe`，或者在套件根目录运行下面的 PowerShell 命令。
2. 填写 1.9 APK、2.4 APK、7.x `StreamingAssets`、补充 ZIP。
3. 离线工具目录选择套件根目录下的 `tools/`，不是 `tools/android/` 或源码中的 `src/tools/`。
4. 输出目录与 `app/`、输入资源、工具目录分开，不让输出目录包含这些输入，也不把输出放进它们内部。
5. 处理签名设置，点击“检查路径”，通过后点击“开始构建”，观察日志。

```powershell
.\tools\python\python.exe -B -s .\app\launch_gui.py .
```

首次安装且没有自有密钥时，可以将四项签名设置全部留空。构建器会在 `user-data/keys/local-build.jks` 生成并复用本机密钥，默认别名 `builder`、默认密码 `android`。已有安装必须使用原来的密钥、别名和密码；新生成一把同名密钥不等于原签名。

将 `user-data/keys` 与个人配置单独保存，后续升级继续使用。不要将个人密钥、密码或存档放入公共仓库或给他人分发的构建器 ZIP。

成功后，在输出目录的日期时间子目录中找到：

```text
崩坏3·2017 独立版.apk
client-videos.zip
build-result.json
build-config.local.json
work/original-build.json
work/logs/
```

GUI 和命令行调用同一套完整构建流程。构建器不会自动下载缺失依赖；离线工具不完整时，先检查解压结构和附件是否完整。详细签名说明见 [桌面构建器](desktop-builder.md)。

## 5. Agent 用命令行构建，或用户希望修改源码

能够操作本地文件和命令时，可以直接使用源码入口，不必代替用户逐个点击 GUI。建议复用发布套件的工具链；仅克隆源码不包含这些工具和游戏输入。

先读取 [构建配置示例](../configs/packager-original.example.json)和 [打包器接口](../src/packager/README.md)。将示例复制为个人配置，例如 `configs/packager-original.local.json`，按实际目录填写下列字段。JSON 路径建议使用 `/`；相对路径以**配置文件所在目录**为基准，绝对路径也可以。

| 字段 | 填写内容 |
| --- | --- |
| `schema` / `mode` | `1` / `original-inputs` |
| `client19` / `client24` | 两个原始 APK 的实际路径 |
| `resources7x` / `supplements` | `StreamingAssets` 目录 / 补充 ZIP 或已解压目录 |
| `tools_root` | 套件中的 `tools/android`，注意不同于 GUI 的工具目录 |
| `zig` | `tools/zig/zig.exe` |
| `ffmpeg` | `tools/ffmpeg/ffmpeg.exe` |
| `voice_decoder` | `tools/vgmstream/vgmstream-cli.exe` |
| `wheelhouse` | `tools/wheelhouse`，使用离线套件时显式填写 |
| `keystore` / `key_alias` | 已有签名文件 / 对应别名 |
| `work_dir` | 本轮专用的、尚不存在的构建目录，与源码及输入分开 |

以下命令在源码根目录执行；`$builderPython` 是实际套件的 `tools/python/python.exe` 绝对路径，由 Agent 根据现场位置赋值。工具套件和源码不在同一目录时，不要照抄相对工具路径。

```powershell
& $builderPython -B -m packager build --target apk --config .\configs\packager-original.local.json
```

执行前，向构建进程提供 `BH3_KEYSTORE_PASSWORD` 与 `BH3_KEY_PASSWORD` 环境变量。不要把密码写入公共配置、命令行参数或日志。命令行入口不会自动生成签名密钥：首次构建可先用 GUI 建立密钥；也可用套件 JDK 的 `keytool.exe` 创建个人密钥，别名和路径必须与配置一致。

例如，为**新安装**创建新密钥时，先设置上述两个环境变量；令 `$keytool` 为实际 `tools/android/jdk/*/bin/keytool.exe`、`$keystore` 为尚不存在的目标文件路径，再执行：

```powershell
& $keytool -genkeypair -noprompt -storetype JKS -keystore $keystore -alias builder -keyalg RSA -keysize 2048 -validity 10000 -dname "CN=Offline Local Build" -storepass:env BH3_KEYSTORE_PASSWORD -keypass:env BH3_KEY_PASSWORD
```

正常完整构建执行表单恢复、原生补丁、运行数据、客户端资源、语音/视频转换、Android 编译、APK 组装、对齐和签名。命令行产物在 `work_dir` 内：`candidate.apk`、`embedded/client-videos.zip`、`original-build.json` 和 `logs/`。

失败后先查 `original-build.json` 的错误阶段和对应日志。同一配置、输入、源码未变化且记录状态为 `failed` 或 `incomplete` 时，可继续原任务：

```powershell
& $builderPython -B -m packager.original --config .\configs\packager-original.local.json --resume
```

不要对成功构建使用 `--resume`，也不要在更换输入或修改源码后盲目复用旧阶段。需要重建时先保留必要产物和失败证据，再使用明确的新工作目录；不要为了每次小修复长期积累整套大包。`--target data` 和 `--target tables` 只生成数据，不会产生可安装 APK。

修改源码时先遵守 `AGENTS.md`，具体模块见 [源码与开发入口](roadmap.md)。使用相应回归验证改动；构建成功与手机上的实际玩法验证分别记录。

## 6. 准备兼容存档

已有本项目存档的用户可以继续使用。新玩家从 [BH-LOCRENASCI-ACT-EDIT Releases](https://github.com/ClearwSea/BH-LOCRENASCI-ACT-EDIT/releases) 获取存档编辑器，查看其 [Android 使用说明](https://github.com/ClearwSea/BH-LOCRENASCI-ACT-EDIT/blob/main/docs/使用方式-Android.md)。它用于配套离线版的 `account.json`，不是官方在线账号转换工具。

编辑器中选择模板，点击“使用模板新建”，再保存为一个新文件：

- **新号**：从 1 级白练开始。希望看到开场 CG 并进入第一关时，先确认所选编辑器和 Android 构建均支持该开场流程，再在 1 级新号上勾选“首次登录”；本文编写时编辑器默认不勾选，实际选项和兼容条件以当前版本说明为准。
- **满级体验号**：用于体验角色、装备和关卡，模板进度与装备范围以编辑器说明为准，不代表所有内容已完整实测。

保存为 `account.json` 便于识别。保留原存档副本，不直接覆写用户唯一存档。仅修改舰长等级不等于角色和装备同步升级，也不能保证与新手引导阶段一致；首次游玩优先使用未任意改动的新号模板或体验模板。

## 7. 安装与首次游玩

1. 将 APK、同次构建的 `client-videos.zip` 和 `account.json` 传到手机可选择的位置。
2. 首次安装 APK；覆盖更新前先按下一节备份，并确认签名沿用。
3. 打开应用启动页，点击“选择资源包”，选择 `client-videos.zip`。不要选择 Windows 构建器 ZIP 或补充 ZIP，也不需要手工解压视频包。
4. 点击“选择存档”，选择 `account.json`。已有资源和存档时可直接沿用；重选存档会在开始游戏时确认替换，先确认旧进度是否需要保留。
5. 选择伤害模式：默认开启辅助 **20×**，关闭为正常 **1×**。改变后需彻底退出并重新打开应用生效。
6. 点击“开始游戏”，等待资源准备和本地服务启动。首次准备期间查看状态，不能仅因耗时就清数据或卸载。
7. 进入配套离线版登录界面后，账号和密码可随意填写，本地不做账号密码检查；不需要官方账号。新号开场是否自动播放取决于所选模板。

有设备操作工具且用户已授权安装时，可检查连接设备并操作；多个设备要指定目标。只有构建授权时，不自动替换手机存档。无法操作手机时，将上述步骤交给用户，并请其反馈停在哪个页面。

交付前核对构建回执成功、APK 和视频包存在，并记录文件大小与 SHA-256。让用户至少验证：能进入舰桥或新号开场、能进入并结束一个普通关卡、重启后进度保留。没做实机测试时明确标记“构建成功，实机待验证”。

## 8. 更新、备份和回退

更新前在启动页使用“导出当前存档”，确认备份保存在应用目录之外。应用内的旧档备份会随卸载被删除，不能作为卸载前唯一备份。

使用原签名密钥构建新 APK，再覆盖安装；配套视频按该轮构建提供。仅更新电脑上的构建器不会改变手机已安装版本。签名不匹配时先找原密钥，不要直接卸载解决；必须更换签名时，先确认可恢复的外部存档备份，再由用户决定是否卸载。

保留当前可用 APK、对应视频包、签名密钥和必要存档。回退也须核对存档兼容性，不能保证新版写入的存档可被任意旧版读取。

## 9. 常见问题：从证据定位

| 现象 | 优先检查 |
| --- | --- |
| 找不到原始客户端或完整资源 | 这些不在仓库和构建器内；告知用户缺少的输入及 README 参考入口 |
| “7.x 目录缺少 Audio/Video” | 选择的是不是直接包含两者的 `StreamingAssets`；不要选择上一级游戏目录 |
| “离线工具包不完整” | ZIP 是否完整解压；GUI 是否选到 `tools/`；CLI 的 `tools_root` 是否指向 `tools/android/` |
| 原生指纹、补丁前像不匹配 | 输入内部库是否属于支持版本；保留实际哈希和错误，不能删除校验或硬套地址 |
| 缺少 CG 或素材 | 补充包版本/结构、7.x资源覆盖和 `original-build.json` 的失败阶段 |
| 构建目录已经存在 | 首次构建要求新目录；未完成构建按条件续建，勿直接删除全部历史文件 |
| APK 无法安装或签名冲突 | 手机 ABI、安装错误码、空间和原签名；先保护存档 |
| 启动失败、长时间等待 | 启动页原始错误、本地服务日志、资源包和设备兼容性；区分导入失败与服务失败 |
| 剧情、角色或装备出现 fail/卡死 | 记录版本、设备、角色与装备、关卡/难度、操作顺序，说明必现还是偶发 |

构建问题收集阶段日志与回执；游戏问题收集截图、复现步骤，具备条件时补充 logcat。存档仅在定位需要且用户同意时提供，并移除个人信息。先核对 [已有 Issues](https://github.com/ClearwSea/BH2017-LOCRENASCI/issues)，不要未经用户要求代其发帖或关闭 Issue。
