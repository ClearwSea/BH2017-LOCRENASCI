# 源码与开发入口

仓库同时提供Python本地服务端、兼容适配实现和构建工具。可以直接修改所需模块，按阶段调用脚本；需要生成完整应用时，再选择命令行或图形构建器。

## 从代码开始

1. 阅读[开发约定](../AGENTS.md)与[数据来源](data-sources.md)，确定本次要修改的服务端业务、适配规则或运行组件。
2. 在下方模块索引中找到实现，并准备对应阶段需要的客户端或生成数据。
3. 修改代码或配置，使用相关阶段和隔离检查确认改动；完整应用组装入口见[构建与输入](build.md)。

与Agent协作时，把仓库作为工作目录，说明目标行为、输入版本和期望输出。README、AGENTS及模块文档提供项目上下文，Agent可据此阅读源码、定位实现并继续开发。

Python服务端业务位于`src/server19*.py`，兼容规则位于`src/rules/`及项目配置，Android运行组件位于`src/android-server-probe/`。桌面GUI和命令行调用`src/packager/original.py`组织完整生成流程。

## 输入如何变成APK

| 顺序 | 处理 | 主要输出 |
| --- | --- | --- |
| 1 | 从1.9提取类型、协议与原生库，读取2.4参考表 | 只读分析输入、协议与基础表 |
| 2 | 恢复251张基础表，应用材料导航、跨版本补行、商店与每日使命规则 | 有效服务端表 |
| 3 | 从生成表关联外传、轮回、委托、料理与无尽数据 | 派生目录与客户端表 |
| 4 | 对1.9原生库按依赖顺序应用兼容补丁 | 适配的ARMv7客户端库 |
| 5 | 提取并修补2.4资源，转换7.x语音与USM视频，读取独立补充ZIP | 客户端资源与视频集合 |
| 6 | 配置Python服务端运行数据，编译Android启动界面和承载层 | 运行包、DEX与辅助库 |
| 7 | 组装、对齐和签名 | 单APK、配套视频ZIP与构建记录 |

## 从哪里修改

| 位置 | 适合修改的内容 |
| --- | --- |
| `src/packager/desktop.py`、`src/packager/reference_window.py` | 桌面交互、输入参考与签名帮助 |
| `src/packager/desktop_worker.py`、`src/packager/original.py` | GUI子进程、签名配置与完整构建顺序 |
| `src/packager/core.py`及根目录生成模块 | 独立数据阶段、输入提取与表单生成 |
| `src/packager/runtime_data.py`及资源处理模块 | 服务端运行数据与资源组织 |
| `src/rules/`、`src/profiles/` | 表单差分、派生配方、原生补丁及版本配置 |
| `src/android-server-probe/` | APK内启动界面、Python承载、导入和存档管理 |
| 根目录`server19*.py`及项目配置 | 本地协议和业务规则 |

具体命令与阶段参数见[打包器接口](../src/packager/README.md)。数据来源和自拟规则见[数据与规则来源](data-sources.md)。

## 新增输入版本

1. 登记新输入的参考信息，确认原生库、类型、表字段和资源布局。
2. 为不同的表结构建立字段映射；新增游戏行从对应客户端提取，项目行为保留在独立规则中。
3. 为不同原生库单独适配补丁，确认指纹、指令前像及依赖顺序。
4. 按语音事件和视频覆盖调整转换与补充输入，并生成对应的输出清单。

固定ARM地址的补丁绑定其适配的原生库。7.x资源可能缺少旧内容，使用独立补充包提供对应素材。构建器记录每轮实际输入、阶段结果和产物；通过GUI生成成品后，可在设备上验证运行行为。
