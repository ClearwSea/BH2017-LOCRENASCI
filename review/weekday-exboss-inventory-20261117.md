# 曜日活动与记忆战场静态清点（2026-11-17）

## 范围和依据

- 目标：已发布的 ARM32 `v0.1.7-r4`，源码提交 `952b424`；本次只读清点，没有修改游戏代码、设备或存档，也没有进行实机测试。
- 1.9 原生代码及协议：r4 完整构建的 `work/data/extracted/client19/global-metadata.dat`、原始 1.9 x86 库及 `work/data/generated/protocol/server19_protocol_schema.json`；资源路径另对照 r4 `work/candidate.apk` 的 Unity ResourceManager。
- 表单：同次完整构建的 `work/data/generated/effective-tables/`，这些表由 2.4 输入按 1.9 结构、版本及地区筛选转换，不等同于逐条核实过的 1.9 历史规则；候选关卡行另只读查询 2.4 APK 内的原始类型化表。
- Lua：逐项检查 2.4 APK ResourceManager 与 r4 `work/resources/private/data/bh3-server19-resources/`。资源存在只说明静态输入存在，不能说明全部引用闭合或游戏运行成功。

## 曜日活动

### 共同缺口和实现判断

- 普通曜日候选关卡均不在当前有效 `stagedata_main` 的已部署关卡中。必须有选择地补齐客户端和服务端关卡表、顶层及递归 Lua 依赖、怪物/场景资源，并验证 2.4 Lua 能否由 1.9 客户端运行。示例：角色经验训练的顶层脚本还依赖 `SP_Material_AvatarExp_Bio_Common`，该依赖在 2.4 有、r4 本地目录没有；月光乱舞抽查到的两个基础 Lua 依赖已在 r4 本地目录中。
- 单纯推送活动列表不能完成玩法。还需处理排期、等级与活动次数、币种/体力、进关、结算、重复奖励、失败与重登恢复，以及客户端刷新。`ExchangeWeekDayActivityTimes` 和 `OpenWeekDayActivity` 在原生协议中存在，r4 未发现专门业务实现；是否需要开放这两项，取决于选定活动的原生行为。
- 材料训练新旧两套及每日主题的 104/104 个源关卡行，`firstDisplayDropList` 均为空，而当前普通关卡首通方案要求非空；因此不能未经调整直接套用现有首通奖励路径。这 104 行的 `battleType` 均为 1、`teamNum` 均为 1，但这两项字段不足以排除页面的多人模式或其他联机依赖。`dropList` 的数字格式不能仅凭与 `rewarddata` 的 ID 不重合断定缺失或无法发奖，需另行解析掉落来源及其引用链，再明确兼容奖励规则。
- **判断：材料训练和每日主题均有实际原生页面、表单及原始脚本基础，适合分别进入恢复研究；不是已经接上或保证能玩。**优先选一条单人材料关验证完整链路，再成组覆盖 5 类和其所有难度；每日主题随后按试用角色等额外依赖评估。
- 小队训练 `1701/1711`（各 8 行）及联机降临 `1801/1811/1821/1831`（各 8 行）虽然也能找到 2.4 关卡和 Lua，但脚本路径为 `Lua/Levels/MP/`；本项目没有完整多人后端，不应将其直接当作单人曜日关开放。
- 降临 `1601–1671` 八项、每项 12 行已在 r4 单独接入，四周每周两项循环；本次未重新验证其完整体验。

## 记忆战场（SinDemonEx / ExBoss）

### 1.9 原生入口与协议

原始 1.9 元数据中有 `MonoSinDemonExButton`、`UINavigator.GoToSinDemonEx`、`SinDemonExModule.IsShowEntry/IsAvailable`、备战、战斗及结算处理方法。r4 APK 的原生 ResourceManager 有 `ui/menus/widget/map/sindemonexbutton`、`.../sindemonexmainstubpage`、`.../sindemonexrankpage` 和 `entities/sindemonex/sindemonexuimanager`。这些是原生入口及页面的静态证据；**具体在游戏中出现的位置、触发条件和是否可见未做实机验证**。

原始 1.9 协议包含：

| 命令 | 作用 |
| --- | --- |
| `GetExBossScheduleReq/Rsp` 608/609 | 周期、开启时间、等级与封面 |
| `GetExBossInfoReq/Rsp` 610/611 | 挑战次数、赛程、Boss、成绩和锁定配置 |
| `GetExBossRankReq/Rsp` 627/628 | 排行数据 |
| `ExBossStageBeginReq/Rsp` 629/630 | Boss 和角色编队入场 |
| `ExBossStageEndReq/Rsp` 631/632 | 战斗结果、Boss 和积分结算 |
| `TakeExBossRankRewardNotify` 616、`TakeExBossScoreRewardNotify` 633 | 排名及积分奖励通知 |

r4 Python 服务端未发现对应 ExBoss 专门处理器。普通 `StageBegin/End` 不能视作 ExBoss 专用协议已实现。

### 数据及静态资源

- 当前转换表 `exbossconfig` 有 3 档：38–55 级 4 次、56–69 级 4 次、70–80 级 5 次；是 2.4 参考表的 1.9 结构投影，仍需核实 1.9 原生使用方式与周期重置含义。
- `exbossmonsterdata` 有 285 行、10 个 Boss 名称键；其中 9 个键可在当前文本表解析：帕凡提、教父军团、卡莲、绯狱丸、RPC-6626、阿湿波、地藏御魂、被诅咒的英魂、影骑士·月轮。剩余 `ExBossName_11001` 15 行缺少对应文本。行数包含不同 Boss 难度或变体，不是 285 个不同 Boss，也不代表全部能在 1.9 正常作战。
- r4 APK 的资源索引存在上述九组对应名称的 `entities/sindemonex/boss_012`、`boss_ro_012`、`boss_080`、`boss_070`、`boss_050`、`boss_090`、`boss_100`、`boss_himeko_c4`、`boss_fuka_c2`；未发现 `entities/sindemonex/boss_110`。原始表的完整 Prefab 路径与资源索引短路径并不完全相同，实际加载映射及依赖仍需核实，不能仅凭名字判定资源闭合。
- 排名奖励表 18 行、积分奖励表 72 行；其引用的 `rewardId` 在当前 `rewarddata` 中分别 18/18 和 72/72 找到。只核对了奖励行存在，没有逐项验证物品、显示、发放或数值适合离线玩法。
- 当前文本表描述按周开放、赛程内不同 Boss 的角色和装备锁定；这些也是 2.4 来源的参考文本，不能直接认定为已经实现或严格复原的 1.9 规则。

### 实现判断

**具备恢复基础，但比普通曜日复杂。**可先研究原生入口的开放条件、排期和 Boss 信息响应，用隔离存档验证原生页面；再选择一组资源完整的 Boss，接通组队、专用进关/结算、积分、次数与角色装备锁定，核实原生战斗加载。周期与奖励发放需要防重复和重启恢复；单机排行的显示与结算方式涉及产品规则，须先拿出明确方案供用户决定，不伪造在线玩家或冒充客户端行为。未命名/缺资源的 Boss 单列待核实，不作为首批可交付承诺。

## 已知边界

本次是静态清点和源数据交叉核对，没有启动客户端、安装包、操作设备或修改存档；没有完整追踪所有 2.4 Lua、怪物、场景和音效的依赖链。下一步的工作量和可玩性要以原生客户端实测为准。
