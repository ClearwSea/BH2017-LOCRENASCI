# Issue #20 / #21 复现及调查（2026-11-18）

## #20：补给卡耗尽后界面显示旧数量

r4 的 `_charge` 在消耗到零时记录卡片 ID，`notification_snapshot` 也会生成数量为 0 的原生装备数据条目；但 `response` 的 `finally` 在 `server19.py` 实际组包之前清除了该线程记录。结果只有内部验证用的快照包含零数量，真正发送的快照缺失此条目。存档已正确扣减，随后提示数量不足符合实际库存，界面未清零是缺陷。

修复为成功时保留待发送的零数量，生成实际出站快照后清除；失败请求清空待发送记录。独立测试覆盖标配角色、标配装备、精准、扩充，以及不足时不发送虚假清零；实机验收尚待完成。
